# TSUGU AI

**会社を継ぐ前も、継いだ後も。いつもそばにいる AI 経営参謀。**

事業承継に向き合う「先代」と「後継者」が、それぞれ AI 面談で考えを言葉にし、**本人が相手への共有を許可した回答だけ**を比べて認識のずれを見つけ、後継者の学習プランと 90 日行動計画につなげるサービスです。

「Built with Claude: Japan 2026」ハッカソン応募作品です。

- 公開 URL：https://tsugu-ai.vercel.app
- デモの会社：架空の和食店「食事処 つぐみ」（創業 1968 年・年商約 5,400 万円・赤字の“踏ん張りどころ”の店）

> デモに登場する会社・人物・数字はすべて架空です。AI の出力は参考情報であり、継ぐ／継がない、税務・法務・融資・企業価値についての判断は専門家にご確認ください。

## なぜ作るのか

日本には、家族が営む店や会社を次の世代へ引き継ぎ、地域の雇用や取引先との関係、商いの知恵を守ってきた家業の文化があります。

その一方で、後継者が「いない」「未定」の企業はいまも多く残っています。帝国データバンクの調査では、2025 年の後継者不在率は **50.1%**（7 年連続で低下）、小規模企業に限ると **57.3%** です。

> 出典：帝国データバンク「全国『後継者不在率』動向調査（2025年）」2025 年 11 月 21 日公表 https://www.tdb.co.jp/report/economic/20251121-successor25y/

### 「見て覚える」承継から、理解し合える承継へ

家業の現場では、先代の仕事ぶりを見て覚える引き継ぎが多く行われてきました。実践で学べる良さがある一方で、判断の理由や仕事の手順が言葉になっていないと、後継者は何を・なぜ・どこまで学べばよいか分かりません。先代も、自分には当たり前の知識を伝えきれません。すれ違いや負担が重なると、後継者が承継を諦めることもあります。

小さなお店では特に、経営の大事なこと（借入の返済、仕入れの口約束、原価の感覚）が**先代の頭の中だけ**にあり、後継者は「何を知らないのか」も分からないまま引き継ぎます。この規模のお店には、経営コンサルタントを雇う余裕もありません。

TSUGU AI は、面談を通じて先代の暗黙の知識と双方の考えを言葉にし、本人が共有を選んだ内容から確認すべきことを示し、学習と 90 日の行動につなげます。「たたむか継ぐか」を決める道具ではなく、**継いで立て直すために、数字と勘を次の世代に渡す道具**です。現場の経験や最終判断を AI が代わりに行うことはありません。

### 面談は「先代の思いを記録に残す」ためのもの

AI 面談は、ただ会話をするためのものではありません。先代の思い・こだわり・判断の理由を言葉にして**記録として残す**ためのものです。一度残しておけば、先代は同じ話を何度も繰り返さなくても、伝えたい人に自分の思いを伝えられます。そのため AI は、思いの理由や、それが表れた具体的な場面まで、やさしく聞き出します。

今回のデモで共有できる相手は先代と後継者のあいだだけで、共有するかどうかはテーマごとに本人が選びます。将来は、本人が選んだ相手（従業員、取引先、銀行・専門家など）にも、本人が共有を認めた記録だけを伝えられるようにしていく構想です。

## デモの流れ（3 分）

1. 先代が AI 面談で回答する
2. 後継者が AI 面談で回答する
3. 二人とも共有を許可したテーマの回答だけで比較し、AI が認識差（例：資金繰り）を「追加確認が必要な点」として提示する。あわせて「守りたいこと／変えられること／新しく試したいこと」を、先代・後継者どちらの意見かを分けて整理する
4. 診断結果を受けて後継者の学習プランが変わる（診断前は「原価率と棚卸しの基本」が1番目 → 診断後は「資金繰りの基本」が1番目に。前のプランと並べて表示）
5. 90 日行動計画ができる（担当・期限・状態・文を二人で直せる。「小さく試す」行動も入る）

1〜5 はすべて公開 URL で動作します。架空の「つぐみ」の想定回答で 5 手順を画面操作で通すスクリプト（`scripts/demo-run.mjs`）と、非公開回答の漏えいを実ブラウザで確かめるスクリプト（`scripts/leak-e2e.mjs`）で、本物の Claude と Turso を使って確認しています。

### 3 分デモの後に使える機能

| 機能 | 内容 |
|---|---|
| 踏ん張れば伸びる余地 | 改善策 4 つ（棚卸し・ランチ価格・宴会の仕組み化・シフト）の効果をアプリが計算。営業利益 ▲236 万円 → 約 +122 万円（仮定の試算で、実現を保証しません） |
| AI 参謀 | お店の数字と二人で共有した診断をもとに、論点の整理・選択肢・相談先（銀行／税理士／その他の専門家）を示す。会話は本人だけに表示 |
| 講座の「AI に質問する」 | 記事ごとに、その記事の本文だけを材料に言葉や数字を説明。記事にない数字は推測しない |
| 決算サマリー・相談資料 | 8 章の決算サマリーと銀行向け相談用資料の下書き。数字はアプリ、文は AI。印刷できる |

### 試し方

1. トップで「先代として入る」を選び、AI 面談に答える（各テーマの最後に要約を確認し、共有するかを選ぶ）
2. 「役割を切り替える」から「後継者として入る」を選び、同じように答える
3. 後継者のまま「学習プラン」を一度作る（診断前のプラン）
4. 「認識差の比較」で［AIに認識差を整理してもらう］
5. 「学習プラン」を作り直す（診断を反映した順番に変わり、前のプランと並ぶ）。講座を受けて小テストに答え、記事の横の「AIに質問する」も試せます
6. 「90日行動計画」で下書きを作り、担当・期限・状態・文を直す
7. 「資料」で決算サマリー・相談資料を作る／「AI参謀」に相談する

最初からやり直すときは、トップの「デモをやり直す」を押してください。

## Claude の使い方

| 場面 | Claude の役割 | アプリ（ルール）の役割 |
|---|---|---|
| AI 面談 | 相手の言葉を受け止め、一度に一つだけ聞き返す。あいまいな回答だけを最大 2 回深掘りし、テーマごとに要約する。相手の知識レベル（Lv1〜4）に合わせて言葉を選ぶ | 会話履歴とテーマの進行・深掘り回数を保存し、毎回 system と messages を組み立てる。返事は JSON（構造化出力）で受け取り、画面には返事の文だけを表示する |
| 要約と共有 | 「本人が話したこと」「AI が気づいたこと（推測）」「確認が必要なこと」に分けて要約する | 本人が確認・修正したものだけを保存。共有するかは本人がボタンで選び、AI には決めさせない |
| 認識差の診断 | 共有済みの要約と数字を読み、共通点・認識の違い（根拠と重要度つき）・確認事項・二人で話し合う問いを整理する | 比率や現金の動きは**アプリが先に計算**して渡す。AI に計算させない |
| これからの選択肢 | 共有済みの要約から「守りたいこと／変えられること／新しく試したいこと」を、誰の意見かを区別して並べる。良し悪しは決めない | 材料は二人とも共有したテーマだけ。お店の数字からは作らせない |
| 学習・90 日計画 | 用意された講座の中から順番を提案し、行動を「誰が・何を・いつまでに」の下書きにする | 講座の中身と問題は固定。採点・理解度の判定はアプリが行う。期限の範囲もアプリが確かめる |
| 講座の質問 | その記事の本文だけを根拠に、知識レベルに合わせて説明する（Lv1 はたとえ話、Lv2 は問いかけ） | 記事・正解は固定。答えは保存しない |
| AI 参謀 | 数字の意味の説明、選択肢と前提条件、相談先の仕分け | 数字と試算はアプリが計算して渡す。面談の内容や相手の会話は渡さない |
| 決算サマリー・相談資料 | 強みと課題、銀行・税理士に相談することの質問リスト | 表の数字は表示のたびにアプリが計算し、AI の出力では上書きできない |

面談の指示文には、先代用・後継者用の追加指示と「良い返事・悪い返事」の例を入れ、決めつけない・結論を出さない・責めない聞き方を安定させています。

## プライバシーの設計

- 共有を許可していない回答は、**内容だけでなく存在も**相手の画面・比較画面・診断に出しません。
- 診断（とそこから作る学習プラン・90 日計画・資料）の材料は、**二人とも共有したテーマ**だけです。共有を取り消すと、それらは同じトランザクションの中で消えます。
- AI 参謀の会話は本人だけのものです。相手の画面にも、診断・計画・資料にも使いません。
- 絞り込みはすべてサーバー側で行います。比較・診断用のデータは SQL の段階で「確定済み かつ 共有済み」の行だけを読みます。
- 面談中の AI には、今の相手の会話と本人が確定した要約だけを渡し、相手の会話は渡しません。
- 公開デモでは、閲覧者ごとに推測できないデモ用 ID を発行し、他の閲覧者のデータは見えません。
  - 同じブラウザ内では「先代」「後継者」を切り替えて両方の立場を体験できます。本番では別々のログインになる想定です。
- デモのデータは、最後に使ってから 7 日たつと自動で削除されます（ブラウザのクッキーの有効期限と同じ）。AI の利用回数の記録だけは、上限を守るために残ります。

## 今後の構想：先代の技術と知恵を、学べる道筋に

事業承継で引き継ぐべきものは、財務や経営の知識だけではありません。先代が現場で培ってきた技術、判断の勘どころ、仕事へのこだわりは、本人にとって当たり前であるほど言葉にならず、「見て覚える」しかないまま失われがちです。

TSUGU AI は将来、AI との対話で先代の仕事の場面・手順・判断の理由を少しずつ聞き取り、先代が確認して共有を認めた内容だけを、後継者が基礎から応用へ段階的に学べる「教えるロードマップ」と教材にしていくことを目指します。財務・資金繰りの講座と、その事業に固有の技能を学ぶ道筋の両方を備え、技術と商いの知恵を次の世代へつなぎます。

今回のハッカソンでは、その入口として、面談の「業務の勘どころ」（仕込み・発注・値決めの判断）などで先代の経験を言葉にし、共有された内容を診断と 90 日行動計画につなげるところまでを実装しました。技能の教材化と指導ロードマップは今後の拡張です。AI は対話を支える役割であり、現場での指導や経験を代わりに行うものではありません。

## 今後の構想：どの業種の承継にも使える「設定ダッシュボード」

今回のデモは、架空の和食店「食事処 つぐみ」1 社分の設定（会社の概要・先代と後継者・知識レベル・決算の数字・面談テーマの補足・講座・改善策の候補）をコードに持たせて動かしています。

将来は、利用する会社が**設定ダッシュボード**で自社の状況を記入・記録し、その会社と面談相手に合わせた TSUGU AI を用意できるようにします。

| ダッシュボードで設定するもの | 例 |
|---|---|
| 業種 | 飲食店／製造業（自動車部品の工場など）／小売／建設 など |
| 会社の概要 | 規模、創業年、主な取引先、従業員数 |
| 面談する人 | 先代・後継者の名前、関係（身内／従業員／第三者）、知識レベル |
| 決算の数字 | 売上・原価・人件費・借入・返済など（比率や現金の動きはアプリが計算） |
| 面談で聞きたいこと | テーマごとの補足（製造業なら「段取り・品質の見方・設備の判断」など） |

業種ごとに「テーマの補足」「講座」「改善策の候補」の型を用意しておき、ダッシュボードで選んだ業種に合わせて切り替えます。6 つの面談テーマの骨組み、共有したものだけを比べる仕組みと非公開の回答を守る仕組み、診断から学習・90 日計画・資料・AI 参謀への流れ、「結論は出さず専門家に確認」という決まりは、どの業種でもそのまま使えます。業種ごとに別のアプリを作るのではなく、1 つの TSUGU AI を会社ごとの設定で使い分ける形です。

## 技術構成

- Next.js 16（App Router）+ TypeScript
- Vercel（公開）
- Turso（libSQL。行ごとの権限制御がないため、アクセス制御はアプリ側で実装・テスト）
- Claude API（Claude Opus 5.5、構造化出力）
- Vitest（漏えいテストを含む自動テスト）

## ローカルでの起動

```bash
npm install
npm run dev
```

`.env.local`（Git には含めません）に次の変数を設定します。

| 変数名 | 内容 |
|---|---|
| `ANTHROPIC_API_KEY` | Claude API キー（サーバー側でのみ使用） |
| `TURSO_DATABASE_URL` | Turso の接続先（`libsql://…`） |
| `TURSO_AUTH_TOKEN` | Turso の認証トークン |
| `CLAUDE_MODEL` | 使用するモデル名（省略時は `lib/config.ts` の既定値） |
| `AI_DAILY_CALL_LIMIT` | アプリ全体の 1 日の AI 呼び出し上限（省略時 2,000。日本時間の毎朝 9:00 に戻る） |

| コマンド | 内容 |
|---|---|
| `npm test` | 自動テスト（非公開回答が漏れないことの確認を含む） |
| `node scripts/demo-run.mjs <URL> screenshots/<名前>` | 5 手順と追加機能を画面操作で通し、画面写真を撮る（本物の AI を約 35 回使う） |
| `node scripts/leak-e2e.mjs <URL>` | 非公開回答の目印が相手の画面・通信に出ないことを確かめる |
| `npm run check:claude` | Claude API の接続確認 |
| `npm run check:db` | Turso の接続確認 |

## 開発について

- 開発にはオーナー自作の Claude Code 開発チーム定義（CTO＋専門サブエージェント 8 名、`.claude/agents/`）を使用しています。CTO 役の Claude Code が画面・サーバー・テスト・セキュリティ点検の各エージェントに委任しながら開発しました。
- これらは開発を補助するための設定ファイルであり、アプリケーションのコードはすべてハッカソン期間中（2026-11-02 12:00 以降）に新規作成しました。
- 既存プロジェクト（他のアプリや既存の AI マネージャー）のコードは流用していません。
- 3 分デモの 5 手順を先に完成させ、そのあとオーナーの判断（2026-11-03）で「伸びる余地の試算」「AI 参謀」「講座の AI に質問する」「決算サマリー・相談資料」を追加しました。
- コード内のコメントにある「Notion」は、非公開の仕様書（要件・指示文・デモ会社の設定）を指します。「SEC-」「REV-」で始まる番号は、開発中のセキュリティ点検・コードレビューの指摘番号です。
