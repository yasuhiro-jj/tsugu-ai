# TSUGU AI

**会社を継ぐ前も、継いだ後も。いつもそばにいる AI 経営参謀。**

事業承継に向き合う「先代」と「後継者」が、それぞれ AI 面談で考えを言葉にし、**本人が相手への共有を許可した回答だけ**を比べて認識のずれを見つけ、後継者の学習プランと 90 日行動計画につなげるサービスです。

「Built with Claude: Japan 2026」ハッカソン応募作品です。

- 公開 URL：https://tsugu-ai.vercel.app
- デモの会社：架空の和食店「食事処 つぐみ」（創業 1968 年・年商約 5,400 万円・赤字の“踏ん張りどころ”の店）

> デモに登場する会社・人物・数字はすべて架空です。AI の出力は参考情報であり、継ぐ／継がない、税務・法務・融資・企業価値についての判断は専門家にご確認ください。

## なぜ作るのか

日本には、家族が営む店や会社を次の世代へ引き継ぎ、地域の雇用や取引先との関係、商いの知恵を守ってきた家業の文化があります。

その一方で、後継者が「いない」「未定」の企業はいまも多く残っています。帝国データバンクの調査では、2025 年の後継者不在率は **50.1%**（7 年連続で低下）、小規模企業に限ると **57.3%** です。

> 出典：帝国データバンク「全国『後継者不在率』動向調査（2025年）」2025 年 11 月 21 日公表 https://www.tdb.co.jp/report/economic/20251121-successor25y/

### 「見て覚える」承継から、理解し合える承継へ

家業の現場では、先代の仕事ぶりを見て覚える引き継ぎが多く行われてきました。実践で学べる良さがある一方で、判断の理由や仕事の手順が言葉になっていないと、後継者は何を・なぜ・どこまで学べばよいか分かりません。先代も、自分には当たり前の知識を伝えきれません。すれ違いや負担が重なると、後継者が承継を諦めることもあります。

小さなお店では特に、経営の大事なこと（借入の返済、仕入れの口約束、原価の感覚）が**先代の頭の中だけ**にあり、後継者は「何を知らないのか」も分からないまま引き継ぎます。この規模のお店には、経営コンサルタントを雇う余裕もありません。

TSUGU AI は、面談を通じて先代の暗黙の知識と双方の考えを言葉にし、本人が共有を選んだ内容から確認すべきことを示し、学習と 90 日の行動につなげます。「たたむか継ぐか」を決める道具ではなく、**継いで立て直すために、数字と勘を次の世代に渡す道具**です。現場の経験や最終判断を AI が代わりに行うことはありません。

## デモの流れ（3 分）

1. 先代が AI 面談で回答する
2. 後継者が AI 面談で回答する
3. それぞれが共有を許可した回答だけで比較し、AI が認識差（例：資金繰り）を「追加確認が必要な点」として提示する
4. 診断結果を受けて後継者の学習プランが変わる（「資金繰りの基本」が最優先に）
5. 90 日行動計画ができる（担当・期限・状態を更新できる）

1〜5 はすべて公開 URL で動作します（本物の Claude と Turso を使った通し確認 22 項目で確認）。

### 試し方

1. トップで「先代として入る」を選び、AI 面談に答える（各テーマの最後に要約を確認し、共有するかを選ぶ）
2. 「役割を切り替える」から「後継者として入る」を選び、同じように答える
3. 「認識差の比較」で［AIに認識差を整理してもらう］
4. 後継者のまま「学習プラン」を作り、講座を受けて小テストに答える
5. 「90日計画」で下書きを作り、行動の状態を更新する

最初からやり直すときは、トップの「デモをやり直す」を押してください。

## Claude の使い方

| 場面 | Claude の役割 | アプリ（ルール）の役割 |
|---|---|---|
| AI 面談 | 相手の言葉を受け止め、一度に一つだけ聞き返す。あいまいな回答だけを最大 2 回深掘りし、テーマごとに要約する。相手の知識レベル（Lv1〜4）に合わせて言葉を選ぶ | 会話履歴とテーマの進行・深掘り回数を保存し、毎回 system と messages を組み立てる。返事は JSON（構造化出力）で受け取り、画面には返事の文だけを表示する |
| 要約と共有 | 「本人が話したこと」「AI が気づいたこと（推測）」「確認が必要なこと」に分けて要約する | 本人が確認・修正したものだけを保存。共有するかは本人がボタンで選び、AI には決めさせない |
| 認識差の診断 | 共有済みの要約と数字を読み、共通点・認識の違い（根拠と重要度つき）・確認事項・二人で話し合う問いを整理する | 比率や現金の動きは**アプリが先に計算**して渡す。AI に計算させない |
| 学習・90 日計画 | 用意された講座の中から順番を提案し、行動を「誰が・何を・いつまでに」の下書きにする | 講座の中身と問題は固定。採点・理解度の判定はアプリが行う |

面談の指示文には、先代用・後継者用の追加指示と「良い返事・悪い返事」の例を入れ、決めつけない・結論を出さない・責めない聞き方を安定させています。

## プライバシーの設計

- 共有を許可していない回答は、**内容だけでなく存在も**相手の画面・比較画面・診断に出しません。
- 絞り込みはすべてサーバー側で行います。比較・診断用のデータは SQL の段階で「確定済み かつ 共有済み」の行だけを読みます。
- 面談中の AI には、今の相手の会話と本人が確定した要約だけを渡し、相手の会話は渡しません。
- 公開デモでは、閲覧者ごとに推測できないデモ用 ID を発行し、他の閲覧者のデータは見えません。
  - 同じブラウザ内では「先代」「後継者」を切り替えて両方の立場を体験できます。本番では別々のログインになる想定です。
- デモのデータは、最後に使ってから 7 日たつと自動で削除されます（ブラウザのクッキーの有効期限と同じ）。AI の利用回数の記録だけは、上限を守るために残ります。

## 技術構成

- Next.js 16（App Router）+ TypeScript
- Vercel（公開）
- Turso（libSQL。行ごとの権限制御がないため、アクセス制御はアプリ側で実装・テスト）
- Claude API（Claude Opus 5.5、構造化出力）
- Vitest（漏えいテストを含む自動テスト）

## ローカルでの起動

```bash
npm install
npm run dev
```

`.env.local`（Git には含めません）に次の変数を設定します。

| 変数名 | 内容 |
|---|---|
| `ANTHROPIC_API_KEY` | Claude API キー（サーバー側でのみ使用） |
| `TURSO_DATABASE_URL` | Turso の接続先（`libsql://…`） |
| `TURSO_AUTH_TOKEN` | Turso の認証トークン |
| `CLAUDE_MODEL` | 使用するモデル名（省略時は `lib/config.ts` の既定値） |
| `AI_DAILY_CALL_LIMIT` | アプリ全体の 1 日の AI 呼び出し上限（省略時 500） |

| コマンド | 内容 |
|---|---|
| `npm test` | 自動テスト（非公開回答が漏れないことの確認を含む） |
| `npm run check:claude` | Claude API の接続確認 |
| `npm run check:db` | Turso の接続確認 |

## 開発について

- 開発にはオーナー自作の Claude Code 開発チーム定義（CTO＋専門サブエージェント 8 名、`.claude/agents/`）を使用しています。CTO 役の Claude Code が画面・サーバー・テスト・セキュリティ点検の各エージェントに委任しながら開発しました。
- これらは開発を補助するための設定ファイルであり、アプリケーションのコードはすべてハッカソン期間中（2026-11-02 12:00 以降）に新規作成しました。
- 既存プロジェクト（他のアプリや既存の AI マネージャー）のコードは流用していません。
