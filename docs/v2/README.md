# TSUGU AI 2.0（試作）実装メモ

後継者が決まっていない飲食店の経営者が、一人で面談し、載せる項目を自分で選び、相談資料の下書きを作る試作。
仕様の正は Notion（「04｜継続開発ロードマップ・着手指示書案」ほか）。ここには実装の要点だけを書く。

## いまの状態（段階2：架空データの試作）

- **架空の情報だけ**を使う。実在のお店・人・金額を入力しない。
- **外部の AI・DB にはつながない。** 面談の返事と資料づくりはモック（偽の差し替え部品）、保存はメモリの中だけ。サーバーを止めると消える。
- **本人認証はまだない。** httpOnly クッキーのセッション ID は「同じブラウザの続き」を見分けるだけ。実データを扱う前に、認証・認可・削除・監査を段階3で設計し、第三者の診断を受ける。
- ハッカソン版（既存の画面・API・DB・鍵）は変更していない。

## 置き場所（新規追加のみ）

| 場所 | 中身 |
| --- | --- |
| `app/v2/` | 画面（入口・面談・内容の確認・選択肢・載せる項目・資料の下書き） |
| `app/api/v2/session/` | API（1本） |
| `lib/v2/` | 処理（`service.ts`）、固定の文言（`content.ts`）、モック（`mock.ts`）、メモリ保存（`store.ts`） |
| `components/v2/` | 画面の部品 |
| `tests/v2/` | テスト |

`lib/v2`・`components/v2`・`app/v2`・`app/api/v2` から、既存の `lib/*.ts`（DB・Claude API を含む）は読み込まない。
`tests/v2/leak.test.ts` が読み込み先を調べて確認している。

## 守っている約束と、その場所

- 資料生成に渡すのは、本人が「載せる」に印をつけた項目だけ：`lib/v2/service.ts` の `buildReportInput`
- 「載せる」の初期値はすべて未選択：`buildReviewItems`・`setOptions`
- 内容や選択を変えたら、古い資料は破棄する：`editItem`・`removeItem`・`setOptions`・`setReportSettings`
- 未確認をゼロや「問題なし」に変えない／本人の発言は入力したまま：`buildReviewItems`
- 失敗したら保存せず、作り足さず、やり直し方を伝える：`answer`・`generateReport`
- 自動送信・共有 URL は作らない（操作の一覧にない）：`lib/v2/dispatch.ts`
- 回答・資料の本文をログに出さない：`app/api/v2/session/route.ts`

## 確かめ方

```bash
npm test
```

```bash
npm run dev
```

ブラウザで `/v2` を開く（鍵や DB の設定は不要）。

## まだやっていないこと

- SEC-01・02・04・06（会社どうしの分離、ログイン、権限変更後のアクセス、削除と復元）：認証と本物の DB が前提のため段階3
- 本物の AI での面談（一問ずつ返すか、指示の注入への耐性）
- 第三者による診断、個人情報・法務の専門家確認
- サーバーが複数台になる公開先では、メモリ保存は使えない（手元での試作専用）
